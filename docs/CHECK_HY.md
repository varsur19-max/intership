# Laravel-ի փոքր հավելումով տարբերակ

Ստորև նախորդ տարբերակի ուղեցույցն է։ Այս թարմացման փոփոխությունների, տեղադրման հրամանների և ստուգումների համար նախ կարդա `docs/LARAVEL_HY.md` (docs պանակում՝ `LARAVEL_HY.md`)։ Այս փաթեթում բազայի ֆայլը `intership.sql` է. հին տեքստում նշված `database.sql` և `update.sql` ֆայլերը այստեղ չկան։ Գործող բազան վերաներմուծելու կարիք չկա։ Նախկին ստուգումների նկարագրությունը նոր Laravel մասի գործարկման ապացույց չէ։

---

# Ստուգումներ

Այս փոփոխության համար անցել են JavaScript-ի և Node.js սերվերի շարահյուսության ստուգումները։
Node.js-ում DOM/API փոխարինիչներով ստուգվել են՝ հյուրի, հեղինակի, այլ user-ի ու ադմինի իրավունքները,
խմբագրման/ջնջման կոճակները, «Բոլորը» հղումը դատարկ/սովորական և այդ անունով տարր ունեցող մենյուում,
կատեգորիայով և առանց ֆիլտրի հարցումները, ջնջումից հետո վերադարձը։
PHP և MySQL այստեղ հասանելի չեն, ուստի PHP/SQL-ը իրական սերվերում չի գործարկվել։

Open Server-ում ստուգիր՝

1. Նոր բազայում database.sql, գործող բազայում՝ պահուստավորումից հետո update.sql։ Թարմացումը կարելի է կրկնել։
2. Ստեղծիր երկու user և մեկ admin։ User-ով ավելացրու ապրանք։
3. Հեղինակը կարող է փոխել բոլոր դաշտերը և ջնջել իր ապրանքը։ Այլ user-ը չի կարող՝ նաև API-ով։ Admin-ը կարող է բոլորը։
4. Ջնջումը հաստատում է պահանջում, ջնջված ապրանքը այլևս չի երևում ցանկում կամ մանրամասներում։
5. Ընտրիր կատեգորիա, հետո «Բոլորը»․ պետք է ցուցադրվեն նաև այլ և առանց կատեգորիայի ապրանքները։
6. Նույն full_name-ով, այլ email-ով գրանցումը մերժվում է։ Ստուգիր նաև մեծատառ/փոքրատառ և եզրային բացատներով անունները։
7. Կրկնվող հին անունների դեպքում update.sql-ը ցուցադրում է դրանք։ Տարբերակիր անունները և նորից ներմուծիր։
8. Հին, առանց user_id ապրանքը կարող է փոփոխել միայն ադմինը։
9. Առանց CSRF token-ի փոփոխող API հարցումը մերժվում է։
