# Laravel-ի փոքր հավելումով տարբերակ

Ստորև նախորդ տարբերակի ուղեցույցն է։ Այս թարմացման փոփոխությունների, տեղադրման հրամանների և ստուգումների համար նախ կարդա `docs/LARAVEL_HY.md` (docs պանակում՝ `LARAVEL_HY.md`)։ Այս փաթեթում բազայի ֆայլը `intership.sql` է. հին տեքստում նշված `database.sql` և `update.sql` ֆայլերը այստեղ չկան։ Գործող բազան վերաներմուծելու կարիք չկա։ Նախկին ստուգումների նկարագրությունը նոր Laravel մասի գործարկման ապացույց չէ։

# Ինչպես է աշխատում կոդը

## Կառուցվածքը՝ praktika-ի նման

`index.php`-ն կարդում է `$_SERVER['REQUEST_URI']`-ը, առանձնացնում հարցման մասը և ստուգում հասցեն։ `/api/...` հասցեների համար միացնում է session-ը, db.php-ը և api/index.php-ը։ Էջերի համար բացում է components/head.php-ը։

`components/head.php`-ում կան միայն HTML-ի կմախքը, CSS-ի և մեկ script.js ֆայլի միացումը։ Էջերի բովանդակությունը և form-երը PHP-ում չկան, քանի որ ամբողջ frontend-ը JavaScript-ով ստեղծելու պահանջը պահպանված է։

`script.js`-ում նույնպես սովորական if/else է․ `/` → allProducts, `/show` → showProduct, `/add` և `/edit` → productForm, `/login` → authForm(false), `/register` → authForm(true), `/admin` → adminPage։

## Մեկ form-ի ընթացքը

1. Օրինակ՝ `script.js`-ի productForm ֆունկցիան ստեղծում է անվան, նկարագրության, կատեգորիայի, գնի և քանակի դաշտերը։ HTML-ը գրված է անմիջապես JavaScript-ի մեջ։
2. `submit` իրադարձության մեջ `event.preventDefault()`-ը դադարեցնում է սովորական էջի ուղարկումը։
3. `new FormData(form)`-ը հավաքում է դաշտերի արժեքները։
4. `api('/add', formData)`-ը CSRF token-ն ավելացնում է և fetch-ով POST հարցում ուղարկում։
5. `api/index.php`-ը ստուգում է մեթոդը և token-ը, հետո միացնում `crud/add.php`-ը։
6. `other/auth.php`-ը ստուգում է՝ արդյոք օգտատերը մուտք է գործել և բազայում գոյություն ունի։ Ավելացման դեպքում թույլատրվում է նաև user դերը, մյուս պաշտպանված գործողությունները պահանջում են admin։
7. `crud/add.php`-ը հենց իր մեջ ստուգում է դաշտերը։ Խմբագրման ստուգումները `crud/edit.php`-ում են։
8. `crud/add.php`-ում `$sql`, `mysqli_query($db, $sql)` և `if (!$res)` են՝ ինչպես praktika-ում։
9. PHP-ն վերադարձնում է JSON՝ ավելացված ապրանքի ID-ով։ JavaScript-ը բացում է այդ ապրանքի էջը։

JSON-ի համար օգտագործվում են `echo json_encode(...)` և `exit`։ Ընդհանուր query(), respond(), postText() ֆունկցիաներ չկան։ Կոդը մի փոքր ավելի երկար է, բայց յուրաքանչյուր քայլը երևում է հենց գործողության ֆայլում։

## Ինչու innerHTML և textContent

`innerHTML`-ում միայն ծրագրավորողի գրած հաստատուն HTML-ն է։ Բազայից ստացված անունը և նկարագրությունը տեղադրվում են `textContent`-ով, իսկ form-ի արժեքները՝ `value`-ով։ Այդպես ապրանքի անվան մեջ գրված HTML կամ script-ը ցուցադրվում է որպես տեքստ։

## Մենյուի ծնողն ու երեխաները

`menu_items.parent_id`-ն պահում է ծնողի ID-ն։ Գլխավոր տարրի դեպքում այն NULL է։ Frontend-ի select-ում 0-ը նշանակում է «առանց ծնողի», իսկ PHP-ն դա փոխում է SQL NULL-ի։

`script.js`-ի menuLevel ֆունկցիան ցուցադրում է տվյալ ծնողի երեխաներին։ Նույն ֆունկցիան կառուցում է հաջորդ մակարդակը, իսկ կոճակը բացում կամ փակում է այն։ Ուրիշ թվով առանձին submenu1/submenu2/submenu3 ֆայլեր չկան։

`script.js`-ի menuForm ֆունկցիայում ծնողի ընտրությունից հեռացվում են ընթացիկ տարրը և իր ժառանգները։ PHP-ի `menu/add.php` և `menu/edit.php` ֆայլերը անկախ frontend-ից կրկին ստուգում է նույն կանոնը՝ ծնողից բարձրանալով վերև while ցիկլով։

Տեղափոխումների ժամանակ օգտագործվող START TRANSACTION-ը և FOR UPDATE-ը մի փոքր ավելի առաջադեմ SQL են, բայց անհրաժեշտ են, որպեսզի երկու ադմինի միաժամանակյա հարցումները չստեղծեն ցիկլ։ Բոլոր մենյուի փոփոխությունները հերթով կողպում են menu_lock աղյուսակի մեկ տողը։ COMMIT-ը հաստատում է հաջող փոփոխությունը։ Մինչև COMMIT սխալի պատճառով exit լինելու դեպքում կապի փակվելիս MySQL-ը չհաստատված փոփոխությունը հետ է վերադարձնում։

## Մուտք և իրավունքներ

Գրանցման ժամանակ password_hash-ը պահում է գաղտնաբառի hash-ը։ Login-ում password_verify-ը ստուգում է գաղտնաբառը։ Հաջող մուտքի դեպքում session-ում պահվում են user_id, status, user_name-ը։ Փոփոխող գործողություններից առաջ իրական դերը նորից կարդացվում է բազայից։

Նավիգացիայից կոճակ թաքցնելը միայն հարմարության համար է․ backend-ը նույնպես պարտադիր ստուգում է իրավունքները։ CSRF token-ը session-ից հասնում է JavaScript-ին `/api/session` հարցումով։

## API

GET՝ `/api/session`, `/api/products`, `/api/product?id=1`, `/api/menu`։

POST՝ `/api/register`, `/api/login`, `/api/logout`, `/api/add`, `/api/edit`, `/api/delete`, `/api/menu/add`, `/api/menu/edit`, `/api/menu/delete`։

POST հարցումներում օգտագործվում է FormData և csrf_token։ Խմբագրման/ջնջման հարցումներն ունեն id դաշտ։ Հասցեներին ավելացվում է index.php-ի basePath-ը։

## Անուններն ու բազան

Նախորդ փաթեթում config-ի, SQL-ի և հասցեների անունները տարբեր էին։ Այստեղ բոլորը համաձայնեցված են՝ intership։ Գործող բազան նախ պահուստավորիր, ընտրիր phpMyAdmin-ում և ներմուծիր `update.sql`-ը։ Այն ավելացնում է բացակայող category_id, stock և user_id դաշտերը և օգտանվան UNIQUE սահմանափակումը։ Եթե հայտնվեն կրկնվող անուններ, ձեռքով տարբերակիր դրանք և կրկին ներմուծիր ֆայլը։ Առանց հայտնի հեղինակի հին ապրանքները կառավարում է միայն ադմինը։ Նոր, դատարկ բազայի համար օգտագործիր `database.sql`-ը։ products.category_id-ն կապված է menu_items.id-ին։ GET /api/products?category_id=1-ը վերադարձնում է միայն ընտրված կատեգորիայի ապրանքները։

## Միավորված JavaScript

Բոլոր frontend ֆունկցիաները մեկ `script.js`-ում են՝ բաժինների հայերեն մեկնաբանություններով։ `authForm(register)`-ը կառուցում է մուտքի կամ գրանցման ձևը։ `productActions`-ը ավելացնում է խմբագրման ու ջնջման կոճակները։ `isDescendant`-ը while ցիկլով բարձրանում է տարրի ծնողներով և թույլ չի տալիս ընտրել իրեն կամ իր ժառանգին։ `async/await`-ը սպասում է PHP-ի պատասխանին, իսկ try/catch-ը ցուցադրում է հարցման սխալը։


## Պարզեցված կոդ

Առանձին validation ֆայլեր չկան։ Ապրանքի և մենյուի ստուգումները գրված են համապատասխան `add.php` ու `edit.php` ֆայլերում։

JavaScript-ի `find`-ը գտնում է էջի տարրը, `addLink`-ը ավելացնում է հղում, իսկ `addOption`-ը՝ select-ի տարբերակ։ `onclick`-ը մշակում է սեղմումը, `onsubmit`-ը՝ ձևի ուղարկումը։ Ձևերը սովորական HTML են՝ JavaScript-ի տողերի մեջ։ `api`-ն FormData-ն ուղարկում է PHP-ին և կարդում JSON պատասխանը։
