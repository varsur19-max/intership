# Intership — Laravel նախագիծ

Ապրանքների կատալոգ՝ օգտատերերով, նկարներով, բազմամակարդակ կատեգորիաներով և հայերեն/անգլերեն միջերեսով։

## Ինչ է փոխվել

- `public/js/app.js` ֆայլը 973 տողից կրճատվել է մինչև 77 տող։ Գործառույթները տեղափոխվել են թեմատիկ ֆայլեր։
- Blade-ի երկար inline CSS-ը տեղափոխվել է `public/css/app.css`։ Կան կանաչ/կրեմագույն գույներ, կողային կատեգորիաներ, ապրանքների քարտեր, նոր ձևեր և փոքր էկրանի դասավորություն։
- Հին HTTP պատասխանը այլևս չի վերագրում արդեն բացված նոր էջը։ Օրինակ՝ ապրանքների բեռնումից անմիջապես հետո խմբագրման ձև բացելիս հին հարցումը չի փակում ձևը։
- Վերջին էջի վերջին ապրանքը ջնջելիս ցուցակը վերադառնում է հասանելի վերջին էջին։
- Կատեգորիայի drag-and-drop տեղափոխումը փոխում է միայն ծնողին։ Նախկին PUT հարցումը ուղարկում էր նաև հին անունը և հերթականությունը, որոնք կարող էին վերագրել ավելի նոր խմբագրումը։
- Նկարի փոխարինման ժամանակ ապրանքը վերընթերցվում և կողպվում է transaction-ի ներսում։ Հին նկարը ջնջվում է հաջող պահպանումից հետո։ Հին ֆայլի մաքրման ձախողումը գրանցվում է logs-ում՝ արդեն պահպանված փոփոխությունը սխալ չներկայացնելու համար։
- Bcrypt-ի դեպքում երկար բազմաբայթ գաղտնաբառը վերադարձնում է հասկանալի validation error։ Նախկին `max:72` ստուգումը հաշվում էր նիշերը, մինչդեռ bcrypt-ի սահմանը բայթերով է։
- Չմուտքագրված օգտատիրոջ սովորական HTML հարցումը ուղղորդվում է գլխավոր էջ՝ գոյություն չունեցող `login` route-ից առաջացած սխալի փոխարեն։ JSON հարցումը շարունակում է ստանալ 401։
- Ուղղվել են անգլերենում չթարգմանվող մի քանի տեքստեր, `menu-row` class-ի սխալ թարգմանությունը և նկարի preview-ի CSS selector-ը։
- Կա նկարի նախադիտում, բացակայող նկարի փոխարինող պատկեր, ցանցի սխալի պարզ հաղորդագրություն և localStorage-ի անհասանելիության դեպքում աշխատող լեզվի ընտրություն։ Լեզուն փոխելիս չպահպանված ձևի մասին կա հաստատման հարց։
- Նույն անունով կատեգորիաները ապրանքի ձևում ցուցադրվում են ամբողջ ուղով։
- `UserFactory`-ն ստեղծում է օգտանուն։ Փորձնական seeder-ը կրկնակի գործարկելիս չի կրկնում նույն հաշիվը և production միջավայրում չի ստեղծում այն։
- Ավելացվել են ավտոմատ ստուգումներ։ PHPUnit-ը պարտադիր օգտագործում է առանձին SQLite `:memory:` բազա։

## Ֆայլերի բաժանումը

| Ֆայլ | Պատասխանատվություն |
| --- | --- |
| `public/js/app.js` | Գործարկում, ընթացիկ օգտատիրոջ ստացում, վերևի կոճակներ |
| `public/js/common.js` | Ընդհանուր վիճակ, CSRF-ով `fetch` հարցումներ, սխալներ, հին պատասխանների վերահսկում |
| `public/js/auth.js` | Մուտքի և գրանցման ձևեր, ելք |
| `public/js/products.js` | Ապրանքների ցուցակ, էջավորում, դիտում, ավելացում, խմբագրում, ջնջում, նկար |
| `public/js/menu.js` | Կատեգորիաների ծառ, ֆիլտրում, ադմինի կառավարում |
| `public/js/drag-drop.js` | Ապրանքների հերթականություն և տեղափոխում, կատեգորիաների տեղափոխում |
| `public/js/language.js` | Լեզվի ընտրություն և `t()` թարգմանիչ |
| `public/css/app.css` | Ամբողջ միջերեսի ձևավորում և responsive կանոններ |
| `resources/views/app.blade.php` | Էջի հիմք և CSS/JS ֆայլերի միացում |
| `routes/web.php` | URL-ների կապը controller-ների հետ |
| `app/Http/Controllers` | Հարցումների validation, իրավունքների ստուգում և տվյալների պահպանում |
| `tests/Feature/ProjectRegressionTest.php` | Գործառույթների ավտոմատ ստուգումներ |

Սրանք սովորական JavaScript ֆայլեր են՝ `defer` միացմամբ և ընդհանուր հասանելի ֆունկցիաներով։ ES modules կամ build գործիք պետք չեն։ Blade-ում հերթականությունը կարևոր է՝ `language → common → drag-drop → auth → products → menu → app`։

`resources/js/app.js`-ը Laravel-ի սկզբնական Vite ֆայլն է։ Այս էջը օգտագործում է **public/js/app.js**-ը։ Նույն կերպ իրական նոր ոճը **public/css/app.css**-ում է։

Կախվածությունների ընտրության համար Composer-ում սահմանված է PHP 8.3.26 հարթակը՝ OSPanel-ի այդ տարբերակի հետ համատեղելի փաթեթներ ստանալու նպատակով։ Փաստացի գործարկման թեստերը կատարվել են PHP 8.5-ով։

## Գործող նախագծի թարմացում՝ Windows / OSPanel

1. Պահուստավորիր գործող նախագծի պանակն ու MySQL բազան։
2. ZIP-ի `intership` պանակի ֆայլերը տեղադրիր `C:\OSPanel\home\intership` նախագծի մեջ՝ փոխարինելով կոդի համընկնող ֆայլերը։ Պահպանիր գործող `.env`-ը, `.git`-ը, բազան և `storage/app/public` նկարները։
3. Նախագծի տերմինալում գործարկիր՝

```powershell
cd C:\OSPanel\home\intership
composer install
php artisan optimize:clear
php artisan migrate
php artisan storage:link
php artisan serve
```

`migrate`-ը կատարում է միայն դեռ չկատարված migration-ները։ Այս թարմացման համար նոր migration չի ավելացվել։ **Մի գործարկիր `migrate:fresh`՝ այն ջնջում է բազայի աղյուսակները։ Գործող նախագծում կրկին `key:generate` պետք չէ։**

Արխիվում չկան `vendor`, `node_modules`, անձնական `.env`, logs և runtime cache ֆայլեր։ `composer install`-ը վերականգնում է PHP կախվածությունները `composer.lock`-ից։ Նոր CSS/JS-ի համար `npm install` կամ `npm run build` պետք չէ։

### Եթե `storage:link`-ը հայտնում է, որ պանակն արդեն կա

Սկզբնական արխիվում `public/storage`-ը սովորական պատճենված պանակ էր։ Այն չի թարմանում `storage/app/public`-ում նոր նկար ավելացնելիս։

- Եթե քո համակարգում դա արդեն ճիշտ աշխատող symbolic link է, ոչինչ մի փոխիր։
- Եթե սովորական պանակ է, նախ համեմատի՛ր դրա ֆայլերը `storage/app/public`-ի հետ և բացակայող նկարները պատճենիր այնտեղ։
- Պահուստավորելուց հետո սովորական պանակը տեղափոխիր նախագծից դուրս, ապա նորից գործարկիր `php artisan storage:link`։ Մի ջնջիր նկարները առանց համեմատելու։
- Windows-ում հղում ստեղծելու համար կարող է անհրաժեշտ լինել Developer Mode կամ ադմինիստրատորի տերմինալ։

Կայքի նոր տեսքը չերևալու դեպքում կատարիր `Ctrl + F5`։ Asset URL-ների մեջ կա ֆայլի փոփոխման ժամանակը՝ հին cache-ի օգտագործումը նվազեցնելու համար։

## Նոր տեղադրում

Գործող նախագծի թարմացման դեպքում այս բաժինը պետք չէ։

```powershell
composer install
Copy-Item .env.example .env
php artisan key:generate
```

`.env`-ում նշիր քո MySQL կապի իրական արժեքները՝ `DB_CONNECTION=mysql`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`։ Նախ ստեղծիր դատարկ բազան։ Այնուհետև՝

```powershell
php artisan migrate
php artisan storage:link
php artisan serve
```

Գրանցվիր կայքի «Գրանցում» կոճակով։ Հաշիվները սովորական օգտատերեր են․ դեր չեն կարող ընտրել գրանցման ձևով։ Կատեգորիաների կառավարումը հասանելի է միայն բազայում `admin` դեր ունեցող հաշվին։ Գործող բազայի ադմինի դերը պահպանվում է։

`php artisan db:seed`-ը պարտադիր չէ։ Միայն local/testing միջավայրում այն ստեղծում է փորձնական `test_user` հաշիվ՝ `password` գաղտնաբառով, առանց ադմինի իրավունքի։ Մի օգտագործիր այս փորձնական հաշիվը հրապարակված կայքում։

## Ինչպես ստուգել

```powershell
php artisan config:clear
php artisan test
```

Ստուգված է PHP 8.5 և SQLite միջավայրում՝ **20 թեստ, 73 assertion**։ Դրանք ներառում են գրանցում, մուտք/ելք, իրավունքներ, նկարի պահպանում/փոխարինում, սխալ upload, soft delete, կատեգորիաների ցիկլ, parent-only տեղափոխում, էջավորում և հերթականության փոփոխություն։ Սկզբնական երկու օրինակային թեստերն էլ պահպանված են։

Chromium բրաուզերում ստուգվել են գրանցումը, մուտք/ելքը, ապրանքի ավելացում/խմբագրում/ջնջումը, նկարի նախադիտումը, օգտատիրոջ տեքստի անվտանգ ցուցադրումը, անգլերենի ընտրությունը և հին HTTP պատասխանի անտեսումը։ 390px լայնությամբ էջը հորիզոնական արտահոսք չունի։ JavaScript-ի գործարկման սխալներ չեն գրանցվել։

Իրական OSPanel/MySQL սերվերի վրա զուգահեռ հարցումների ծանրաբեռնվածության փորձարկում չի կատարվել։ SQLite-ի թեստերը չեն ապացուցում MySQL-ի locking վարքագիծը։

## Դեռ առկա սահմանափակումներ և հաջորդ բարելավումները

- Միևնույն ապրանքի տեքստային տվյալները երկու օգտատեր միաժամանակ փոխելիս վերջին հաջող պահպանումը հաղթում է։ Նկարների ֆայլերի մրցակցային խնդիրը նվազեցված է, բայց ամբողջ ձևի conflict detection չի ավելացվել։
- Հերթականության փոփոխությունը կարդում և կողպում է ակտիվ ապրանքների ամբողջ ցուցակը։ Փոքր նախագծի համար պարզ է, մեծ կատալոգի համար պետք է ավելի արդյունավետ դիրքավորման մեխանիզմ։
- Կատեգորիայի ֆիլտրը ցույց է տալիս հենց ընտրված կատեգորիայի ապրանքները, ոչ ենթակատեգորիաների բոլոր ապրանքները միասին։
- Կատեգորիաների ծառը կառուցվում է հիշողության մեջ, իսկ շատ մեծ կամ շատ խոր ծառերի համար պետք է օպտիմալացում։
- Drag-and-drop-ը նախատեսված է հիմնականում մկնիկի համար։ Սենսորային էկրանին և ստեղնաշարով կատեգորիան փոխիր խմբագրման ձևով։ Ապրանքների հերթականության համար առանձին ստեղնաշարային կառավարում դեռ չկա։
- Ապրանքի soft delete-ի ժամանակ նկարը պահվում է հնարավոր վերականգնման համար։ Մշտական ջնջման և հին ֆայլերի մաքրման առանձին գործիք դեռ չկա։
- Գաղտնաբառի վերականգնում, էլ․ հասցեի հաստատում, ադմինի հաշիվների կառավարման միջերես և գործողությունների պատմություն այս տարբերակում չկան։
- Գործող ընդհանուր JavaScript վիճակը պահպանված է՝ սկսնակի համար կառուցվածքը պարզ պահելու նպատակով։ Ավելի մեծ հավելվածում կարելի է անցնել ES modules-ի և ավելի խիստ state management-ի։
- Նախագծի AGENTS.md հրահանգով տեղադրված է Laravel Boost՝ միայն development կախվածություն։ Այն հավելվածի գործարկման պարտադիր production բաղադրիչ չէ։

## Փոխել գույներն ու ոճը

Բացիր `public/css/app.css` ֆայլի սկիզբը։ `:root` բաժնի `--paper`, `--green`, `--accent`, `--ink` փոփոխականները կառավարում են հիմնական գույները։ Հետագա բաժինները վերաբերում են header-ին, կատեգորիաներին, քարտերին, ձևերին և փոքր էկրաններին։
