# Intership

Ապրանքների և դինամիկ բազմամակարդակ մենյուի կառավարում՝ PHP, MySQL և JavaScript։
Կառուցվածքն ու գրելաձևը մոտեցված են praktika-ին՝ առանց framework-ի, class-երի կամ ընդհանուր UI կառուցող համակարգի։

## Գործարկում

1. Բացիր ZIP-ը։ Նախագծի պանակը՝ `intership`։
2. Միացրու MySQL-ը և phpMyAdmin-ում ներմուծիր `database.sql`։ Այն ստեղծում է `intership` բազան։
3. `db.php`-ում ստուգիր host/user/password-ը։ Լռելյայն՝ `MySQL-8.0`, `root`, դատարկ գաղտնաբառ։
4. PHP-ի տերմինալում մտիր նախագծի պանակ և գործարկիր․

```powershell
php -S 127.0.0.1:8000 index.php
```

5. Բացիր `http://127.0.0.1:8000/intership/`։
6. Գրանցվիր։ phpMyAdmin-ում քո email-ով կատարիր․

```sql
UPDATE intership.users SET status = 'admin' WHERE email = 'your-email@example.com';
```

7. Մուտք գործիր կամ թարմացրու էջը։ Ապրանքները և մենյուն սկզբում դատարկ են․ նախ ադմինի էջում ստեղծիր կատեգորիաները, հետո user-ով կամ admin-ով ավելացրու ապրանքներ։

Գործող բազան նախ պահուստավորիր, ընտրիր phpMyAdmin-ում և ներմուծիր `update.sql`-ը։ Այն ավելացնում է բացակայող category_id, stock և user_id դաշտերը և օգտանվան UNIQUE սահմանափակումը։ Եթե հայտնվեն կրկնվող անուններ, ձեռքով տարբերակիր դրանք և կրկին ներմուծիր ֆայլը։ Առանց հայտնի հեղինակի հին ապրանքները կառավարում է միայն ադմինը։ Նոր, դատարկ բազայի համար օգտագործիր `database.sql`-ը։

## Node.js-ով բացել

PHP-ի տերմինալը միացված թողնելով՝ երկրորդ տերմինալում, նույն պանակից․

```powershell
npm start
```

Բացիր `http://127.0.0.1:3000/intership/`։ Արտաքին npm կախվածություններ չկան։ Node.js-ը հարցումները փոխանցում է PHP-ին, իսկ PHP-ն աշխատում է MySQL-ի հետ։ Հանրային HTTPS հղման և Open Server/Apache-ի քայլերը՝ `docs/START_HY.md`։

## Հնարավորություններ

- Ամբողջ frontend-ը և բոլոր form-երը ստեղծվում են JavaScript-ով։
- Ապրանքի ավելացում, ցանկ, մանրամասներ, խմբագրում և տրամաբանական ջնջում։
- Անվանում, նկարագրություն, պարտադիր կատեգորիա, գին, քանակ, ստեղծման և փոփոխման ամսաթիվ։
- Գրանցում, մուտք, ելք, user/admin դերեր։ User-ը և admin-ը կարող են ապրանք ավելացնել։ User-ը խմբագրում և ջնջում է իր ապրանքները, admin-ը՝ բոլոր ապրանքները։ Մենյուի կառավարումը միայն ադմինի համար է։
- Մենյուի ստեղծում, ենթամենյու, խմբագրում, ծնողի ընտրություն, տեղափոխում, հերթականություն, ջնջում։
- Մենյուի խորության համար նախապես սահմանված մակարդակների քանակ չկա։ Սլաքին սեղմելիս բացվում են երեխաները, իսկ բաժնի անվանը սեղմելիս ցուցադրվում են միայն հենց այդ կատեգորիայի ապրանքները։
- Տարրը ջնջելիս իր երեխաները տեղափոխվում են մեկ մակարդակ վերև։
- Իրեն կամ սեփական ենթատարրին ծնող ընտրելը մերժվում է նաև backend-ում։
- Տվյալները պահվում են MySQL-ում և չեն կորչում էջը թարմացնելիս։
- CSRF, գաղտնաբառերի hash, մուտքի session, SQL escaping և անվտանգ տեքստի ցուցադրում։

Frontend-ն ունի միայն մեկ JavaScript ֆայլ՝ `script.js`։ `server.cjs`-ը առանձին Node.js սերվերն է և browser-ում չի միացվում։ Մուտքն ու գրանցումը օգտագործում են նույն `authForm` ֆունկցիան, իսկ ապրանքի կրկնվող կոճակները՝ `productActions`-ը։

Կատեգորիան ջնջելիս ապրանքները պահպանվում են ընդհանուր ցանկում՝ առանց կատեգորիայի։ Ադմինը կարող է ընտրել նոր կատեգորիա։ Ապրանքի էջի «Վերադառնալ» կոճակը պահպանում է ցանկից ընտրված ֆիլտրը։ `.osp/project.ini`-ն պահպանված է անփոփոխ։

## Գնի պարզ ստուգում

Գնի ստուգման մեջ regex չկա։ explode-ը բաժանում է գինը ամբողջ և տասնորդական մասերի։ ctype_digit-ը ստուգում է, որ մասերը միայն թվանշաններ պարունակեն։ Ամբողջ մասը՝ մինչև 8 թվանշան, տասնորդականը՝ մինչև 2։ Օրինակ՝ 100, 100.5, 100.50։ Զրոյական գինն ու քանակը թույլատրվում են։ Ստուգումները հենց ավելացման և խմբագրման PHP ֆայլերում են։

Ձևը չի ուղարկվում մինչև կատեգորիաների բեռնումը կամ նախորդ հարցման ավարտը։ Սխալի դեպքում դաշտերը պահպանվում են, հաջողությունից հետո բացվում է ապրանքի էջը։

## Վերջին փոփոխությունները

- «Բոլորը» մենյուի հղումը բացում է բոլոր չջնջված ապրանքները՝ առանց կատեգորիայի ֆիլտրի։ Այն աշխատում է նաև դատարկ մենյուի դեպքում։
- Խմբագրել/Ջնջել կոճակները երևում են ապրանքի հեղինակի և ադմինի համար՝ ցանկում ու մանրամասների էջում։ PHP-ն նույնպես ստուգում է իրավունքը։ Ջնջումը տրամաբանական է՝ is_del = 1։
- Գրանցվելիս full_name-ը եզրերից մաքրվում է բացատներից և ստուգվում բազայում։ Նույն անունը մեծատառ/փոքրատառ տարբերությամբ կրկին օգտագործել չի կարելի։ UNIQUE-ը պաշտպանում է նաև միաժամանակյա գրանցումներից։

## Ինչի համար է menu_lock աղյուսակը

menu_lock-ը ապրանքներ կամ բաժիններ չի պահում։ Այն ունի մեկ տող՝ id = 1։
Մենյուի ավելացման, խմբագրման և ջնջման ժամանակ START TRANSACTION-ից հետո
SELECT id FROM menu_lock WHERE id = 1 FOR UPDATE հարցումը կողպում է այդ տողը։
Մյուս մենյուի փոփոխությունը սպասում է, մինչև առաջինը ավարտվի COMMIT-ով կամ հետ վերադարձվի։
Օրինակ՝ երկու ադմին միաժամանակ կարող են փորձել A-ն դարձնել B-ի ենթամենյու,
իսկ B-ն՝ A-ի ենթամենյու։ Հերթական մշակումը թույլ է տալիս երկրորդ հարցման ստուգմանը
տեսնել առաջին փոփոխությունը և մերժել այդ ցիկլը։ Աղյուսակը և դրա id = 1 տողը պետք է պահպանել։

## Հեղինակ և փոփոխման ամսաթիվ

Ապրանքի էջում ցուցադրվում է հեղինակի անունը, իսկ դրա բացակայության դեպքում՝ «Անհայտ»։
«Փոփոխված» ամսաթիվը հայտնվում է իրական խմբագրումից հետո։ Առանց փոփոխության
պահպանելը ամսաթիվը չի թարմացնում։ Ադմինի խմբագրումը հեղինակին չի փոխում։
Նախորդ բազան թարմացնելու համար ներմուծիր update_product_details.sql-ը։
Նոր բազայի համար օգտագործիր database.sql-ը։
Հին տվյալներում ստեղծման ու փոփոխման նույն ամսաթվով ապրանքները համարվում են
չխմբագրված․ նույն վայրկյանին կատարված հին խմբագրումները տարբերակել հնարավոր չէ։
